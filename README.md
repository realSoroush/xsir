# XSIR — Next.js + TypeScript

نسخهٔ مستقل لندینگ «طرح ویژه اکسیر | 2FX × XS»، منتقل‌شده از سورس نهایی سایت. طراحی، فونت Alibaba، تصاویر اصلی، رنگ‌ها، چیدمان راست‌به‌چپ، انیمیشن جام، آیکون‌ها، متن‌ها، منوی موبایل، مسیرهای داخلی، FAQ و پنجرهٔ فعال‌سازی حفظ شده‌اند.

## اجرای محلی

Node.js نسخهٔ ۲۲ یا بالاتر نصب کنید. داخل فولدر پروژه:

```bash
npm ci
cp .env.example .env.local
npm run dev
```

در ویندوز می‌توانید فایل `.env.example` را دستی کپی و به `.env.local` تغییر نام دهید. صفحه روی `http://localhost:3000` باز می‌شود. بدون تنظیم هیچ کلیدی، محتوای همان سایت اولیه نمایش داده می‌شود.

```bash
npm run typecheck
npm run lint
npm run build
npm start
```

## اتصال Supabase

این لندینگ پیش از انتقال، فرم ثبت‌نام، ورود یا دیتابیس کاربران نداشت؛ ثبت‌نام و احراز هویت در بروکر و فعال‌سازی توسط پشتیبانی انجام می‌شود. بنابراین این نسخه نیز هیچ حساب کاربری، احراز هویت بروکر، پرداخت یا تأیید خودکار واریز اضافه نمی‌کند. Supabase برای مدیریت محتوای سه دوره آماده شده است.

۱. یک پروژه Supabase بسازید.
۲. محتوای فایل `supabase/migrations/202610050001_xsir_content.sql` را یک بار در SQL Editor اجرا کنید. این فایل جدول `xsir_courses`، سیاست RLS خواندن دوره‌های منتشرشده و محتوای فعلی سه دوره را ایجاد می‌کند. Migration را یک بار اجرا کنید؛ برای تغییر محتوا از Table Editor استفاده کنید.
۳. مقدار Project URL و Publishable Key را در `.env.local` قرار دهید:

```dotenv
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLISHABLE_KEY
```

۴. سرور را دوباره اجرا کنید. محتوای دوره‌ها از Supabase خوانده می‌شود؛ کش آن هر ۶۰ ثانیه اعتبارسنجی می‌شود. هنگام نبود اتصال، خطا، محتوای ناقص یا غیرمعتبر، هر سه دوره با محتوای اصلی نمایش داده می‌شوند. تنظیم ناقص باعث تغییر ظاهر یا صفحهٔ خطا نمی‌شود.

جدول فقط شامل محتوای عمومی دوره‌هاست. دسترسی ناشناس و کاربران واردشده صرفاً خواندن ردیف‌های `published=true` است؛ نوشتن عمومی مجاز نیست. تغییرات از داشبورد Supabase انجام می‌شود. هیچ Secret Key یا Service Role Key در فرانت‌اند لازم نیست.

ساختار `content` همان `src/data/courses.json` است. برای حفظ سه دورهٔ موجود، فیلد `id` را ۱، ۲ یا ۳ نگه دارید و نام فایل‌های تصویر و آیکون را تغییر ندهید. `badge1` تنها قالب `<b>...</b>` یا `<b dir="ltr">...</b>` را برای عدد/برچسب پررنگ پشتیبانی می‌کند؛ HTML دلخواه اجرا نمی‌شود.

## پشتیبانی تلگرام

دکمهٔ پایانی «ارتباط با پشتیبانی» مطابق نسخهٔ نهایی غیرفعال و بدون لینک باقی مانده است. دکمه‌های فعال‌سازی دوره، همان پنجرهٔ درخواست و اشتراک‌گذاری تلگرام را باز می‌کنند.

اگر بعداً آیدی رسمی پشتیبانی مشخص شد، برای ارسال درخواست‌های فعال‌سازی مستقیماً به آن گفت‌وگو این مقدار را تنظیم کنید:

```dotenv
NEXT_PUBLIC_SUPPORT_TELEGRAM_URL=https://t.me/YourSupport
```

فقط لینک مستقیم HTTPS تلگرام پذیرفته می‌شود. این تنظیم دکمهٔ غیرفعال انتهای صفحه را تغییر نمی‌دهد. مقادیر `NEXT_PUBLIC_*` هنگام build ثبت می‌شوند؛ پس پس از تغییرشان دوباره deploy کنید.

## انتقال به GitHub

یک repository خالی بسازید. از داخل این فولدر:

```bash
git init
git add .
git commit -m "Migrate XSIR landing to Next.js and TypeScript"
git branch -M main
git remote add origin https://github.com/YOUR_ACCOUNT/YOUR_REPOSITORY.git
git push -u origin main
```

در بستهٔ دانلودی، پوشه‌های `.git`، `node_modules`، `.next` و فایل حاوی کلید خصوصی وجود ندارند. `.env.example` صرفاً نمونه است. GitHub Actions در هر push و pull request، TypeScript، ESLint و build را بررسی می‌کند.

## انتشار روی Vercel

۱. در Vercel گزینهٔ Add New Project را انتخاب و repository را import کنید.
۲. Framework Preset را Next.js انتخاب کنید. Root Directory باید ریشهٔ همین پروژه، جایی که `package.json` است، باشد. اگر این فولدر را زیرپوشهٔ repository قرار داده‌اید، همان زیرپوشه را انتخاب کنید.
۳. Node.js را روی ۲۲ یا نسخهٔ بالاتر پشتیبانی‌شده تنظیم کنید. Build Command: `npm run build`. تنظیم خروجی را روی پیش‌فرض Next.js نگه دارید.
۴. در صورت استفاده از Supabase، متغیرهای بالا را در Environment Variables برای Production و Preview ثبت کنید؛ فایل `.env.local` را به GitHub نفرستید.
۵. Deploy کنید. تغییرات بعدی شاخهٔ main با اتصال GitHub به Vercel منتشر می‌شوند.

هیچ تنظیمات Cloudflare یا وابستگی به ChatGPT Sites برای اجرای این پروژه لازم نیست. فایل‌های تصاویر و فونت‌ها در خود پروژه هستند.

## ساختار پروژه

- `src/app`: App Router، metadata، صفحه و CSS اصلی.
- `src/components`: ساختار همان لندینگ و کارت‌های دوره‌ها.
- `src/lib/interactions.ts`: منو، پنجرهٔ فعال‌سازی، کپی درخواست و پراگرس اسکرول؛ با پاک‌سازی listenerها.
- `src/lib/courses.ts`: دریافت محتوای معتبر یا برگشت به محتوای اصلی.
- `src/lib/supabase/server.ts`: کلاینت خواندن محتوای عمومی، فقط سمت سرور.
- `src/data`: متن‌های اصلی و SVGهای ثابت آیکون‌ها.
- `public/assets`: تصاویر و فونت‌های اصلی، بدون لینک موقت.
- `supabase/migrations`: جدول، دسترسی‌ها و دادهٔ اولیه.
